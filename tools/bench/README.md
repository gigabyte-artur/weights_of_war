# Стенд Weights of War

Инструменты для измерения обучения юнитов **без окна и отрисовки**: прогон
реального `GameWorld` в headless-режиме, сравнение вариантов кода по медианам,
прогон тестов через Gradle-обёртку.

Появились из задачи «улучшить способность юнитов к обучению» (30.10.2026):
именно ими измерялись гауссова мутация, турнирный отбор и четыре эксперимента
с памятью сети (все четыре оказались хуже baseline — результат отрицательный,
но получен замером, а не на глаз).

## Состав

| файл | что делает |
|---|---|
| `wz_bench.py` | точка входа: `run`, `pair`, `tests` |
| `WorldBench.java` | сам стенд: поднимает `GameWorld` с заглушками `Gdx.graphics`/`GL20` |
| `classpath.init.gradle` | достаёт classpath модуля `core`, не трогая `build.gradle` |

## Быстрый старт

```bat
:: один прогон: 60 поколений, таблица по поколениям
python tools\bench\wz_bench.py run 60

:: сравнение HEAD и рабочего дерева, по 6 прогонов на вариант
python tools\bench\wz_bench.py pair 60 --runs 6 --at 51

:: тесты (обходит JAVA_HOME, указывающий на JRE)
python tools\bench\wz_bench.py tests
```

`wz_bench.py` сам находит JDK с `javac.exe` (перебирает `JAVA_HOME` и
`C:\Program Files\Java\jdk*`), сам собирает classpath через Gradle init-скрипт
и сам компилирует стенд. Руками пути прописывать не нужно.

Всё, что стенд создаёт, лежит в `build/bench/` — каталог `build/` уже в
`.gitignore`, репозиторий стенд не засоряет.

## Что печатает

Одна строка на поколение:

```
gen,coreSword,coreArcher,coreShield,corePriest,coreScout,alive,avgFit,maxFit,tick
```

- `core*` — фиты нейросетей-чемпионов своего типа в ядрах;
- `alive` — сколько юнитов живо;
- `avgFit` / `maxFit` — средний и лучший фит по живым юнитам;
- `tick` — на каком тике это поколение наступило.

## Про случайность — важно

В игре `Random` создаётся без зерна (`Neuron.Mutate`, `NeuroNet.RandomWeights`,
`Evolution`, `BuildingCore`), поэтому прогон **не воспроизводится**. Разброс
между прогонами одного и того же кода большой: на 60 поколениях `avgFit`
наблюдался в диапазоне 67–89. Одиночный прогон не доказывает ничего.

Поэтому в стенде намеренно нет флага `seed` (в старом `WorldBench` он был, но
никуда не подключён — это ловушка). Вместо него:

- `pair` делает несколько прогонов на вариант и сравнивает **медианы**;
- в конце печатается разброс и предупреждение, если диапазоны вариантов
  перекрываются — тогда вывод слабый и нужны ещё прогоны.

Для эксперимента с памятью сети это и было главной методической ошибкой:
первые «парные» сравнения по 3 прогона оказались фикцией.

## Главное про dt и gameSpeed (проверено 30.10.2026)

Игровое время за тик = `dt * gameSpeed`, а поколение наступает раз в 60 игровых
секунд. Отсюда:

| режим | игровое время за тик | поколение | что видно |
|---|---|---|---|
| `--speed 60` (по умолчанию) | 1.0 с | 60 тиков | всё, что короче секунды, выключено |
| `--speed 1000` (как в `HeadlessGame`) | 16.7 с | 4 тика | выключено вообще всё |
| `--speed 10` | 1/6 с | 360 тиков | механики от 1/6 с и длиннее |
| `--speed 1` | 1/60 с | 3600 тиков | всё, как в игре; дорого |

Практический вывод: **кулдаун решения 0.25 с, удар, регенерация и затухание «под
атакой» при `--speed 60` не работают по построению**, а не потому, что плохо
сделаны. В настоящей игре `gameSpeed` = 2 при `dt` ≈ 1/60, то есть 30 тиков в
секунду — там эти механики живут.

Поэтому сравнивать варианты, которые трогают поведение, надо при `--speed 10`
(компромисс: 360 тиков на поколение) или `--speed 1` (честно, но ~11 минут на
50 поколений). `--speed 60` годится только для грубых вещей вроде «эволюция
вообще сходится».

## Полезные флаги

| флаг | смысл |
|---|---|
| `gens` (позиционный) | до какого поколения крутить (по умолчанию 60) |
| `--speed` | `gameSpeed`, по умолчанию 60; в headless можно 100–1000 |
| `--max-ticks` | предохранитель по тикам (по умолчанию 400000) |
| `--dt` | шаг кадра, сек (по умолчанию 1/60) |
| `--at` | на каком поколении снимать метрики для сводки (по умолчанию 51) |
| `--runs` | только `pair`: прогонов на вариант (по умолчанию 6) |

## Ограничения

- **GUI не проверяется.** Стенд мерит только обучение и симуляцию; как это
  выглядит на экране, он не показывает.
- **`gradlew lwjgl3:headless` для замеров не годится** — зависает, причём и на
  исходном коде тоже. Именно поэтому стенд поднимает `GameWorld` напрямую.
- **Долгие прогоны.** Реальный `GameWorld` тяжёлый: 60 поколений — порядка
  минуты-двух на прогон; `pair` с 6 прогонами на вариант идёт заметно дольше.
  Для быстрой проверки берите `run 12` или `pair 6 --runs 2`.
- **Побочный эффект.** Игра раз в 10 секунд сохраняет логи нейросетей в
  `neuro_logs/` **в корне репозитория** (так устроен сам `GameWorld`, не стенд).
  Каталог не в `.gitignore` — после прогона его стоит удалить, чтобы он не
  попал в коммит. Файлы стенда лежат отдельно, в `build/bench/`.

## Как добавить свой замер

Метрики печатаются из `WorldBench.main`; чтобы снять новую величину, добавьте
её в строку вывода и в `metrics()` внутри `wz_bench.py` (он разбирает строку по
позициям). Если нужен доступ к приватному полю игры — рефлексия, как в
исходной версии стенда.
